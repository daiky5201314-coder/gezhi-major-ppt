# 飞书云盘交付规则

仅模式 B 的**专业类课程**（主技能中称为“专业大类”，如“计算机类”）执行本流程。单个本科专业、普通咨询和课程索引不上传。生成内容和事实核验仍遵循主技能；本文件只管成品归档。

## 固定目标和身份

- 父文件夹：`专业库资料制作过程文件夹`，`https://gezhiedu.feishu.cn/drive/folder/FE7ofFTbwlTthEdwo1mcdrcknRc`。
- 目标层级：父文件夹 / `<2位门类代码> <门类名称>` / `<4位专业类代码> <专业类名称>`。例如 `08 工学 / 0809 计算机类`。
- 使用飞书 CLI 的 `GEGZI` profile 和用户身份；每条命令显式传 `--profile GEGZI --as user`。写入前用 `lark-cli whoami --profile GEGZI --as user` 核对 `onBehalfOf.openId` 为 `ou_96b49f9068b07cda299a45291051b7c5`。不使用默认 profile、旧账号或 bot 身份。
- 此处只有文件夹标识和预期用户 ID，仓库中不保存 app secret、访问令牌或刷新令牌。CLI 缺失、未授权、身份不符或权限不足时，保留本地成品并请用户完成对应账号授权；不要换账号或换目标目录继续上传。

## 找到唯一目标文件夹

1. 按主技能的研究规则，用适用的教育部本科专业目录确认主题属于专业类，并核对官方门类及专业类代码、名称。不要仅凭主题名称猜代码；单个专业即使可找到所属专业类，也不进入上传流程。
2. 用 `lark-cli drive files list --params '{"folder_token":"FE7ofFTbwlTthEdwo1mcdrcknRc","page_size":200}' --profile GEGZI --as user --format json` 列出父文件夹直接子项，按 `type=folder` 与完整的 `<代码> <名称>` 严格匹配门类。若 `has_more=true`，按返回的 `next_page_token` 继续翻页。
3. 用匹配到的门类文件夹 token 再列直接子项，严格匹配 `<4位代码> <专业类名称>`。仅当每层恰好一个匹配且 `parent_token` 正确时，才把该 token 作为上传目标。目录缺失、重名、层级不符或该主题没有专业类代码时，停止云端交付并报告；不自行创建文件夹。
4. 列出目标文件夹的**全部页**，读取现有文件名和 URL，供版本选择及上传后核验。CLI 命令参数结构以当时的 `lark-cli drive files list --help` 和 `lark-cli schema drive.files.list` 为准；不要把 `--page-all` 输出直接作为单个 JSON 解析。

## 版本和文件名

- 默认三份文件共用一个版本号：`<专业类名称>-PPT内容稿-Vn.0.md`、`<专业类名称>-逐字讲解稿-Vn.0.md`、`<专业类名称>-资料来源与核验表-Vn.0.md`。用户只要求其中一份时，该份也按同一规则选版本。
- 只统计目标文件夹中**该专业类名称和上述交付类型**的 `-Vn.0.md` 文件，取最大 `n` 加 1；没有版本文件时从 `V1.0` 开始。未带版本号的既有文件视为历史稿，原样保留，不占用 `V1.0`。例如已有 `计算机类-PPT内容稿.md` 时，新稿为 `计算机类-PPT内容稿-V1.0.md`；已有 `V1.0` 时，新稿为 `V2.0`。
- 写本地文件前也检查用户指定目录中的同名路径，避免覆盖。若远端或本地已有本次拟用文件名，重新核对版本；不能确定时停止，不覆盖、删除或改名旧稿。
- 若一次上传只有部分成功，记录该版本已成功的文件及 token。仅在确认本地内容和目标文件夹未变化后，补传该版本缺失的文件；绝不对已成功的文件重复 `+create`。无法安全续传时报告部分完成，等待后续处理。

## 上传与核验

在本地生成并完成内容检查后，以最终带版本号的 `.md` 文件执行 `lark-cli markdown +create --folder-token <专业类文件夹token> --file ./<文件名>.md --profile GEGZI --as user --format json`。CLI 的 `--file` 使用当前工作目录下的相对路径；如文件在其他目录，切换到该目录后运行。不要使用 `+overwrite`、`drive +push` 或目录同步来交付这些版本文件。

逐份检查命令退出码和返回的 `ok: true`、`identity: user`、`data.file_token`、`data.file_name`。全部上传后重新列目标文件夹，确认每个新文件的名称、类型、token 和父目录；用返回的 URL 交付文件链接。若当前 CLI 不返回 URL，可使用该飞书域名和已核实的 file token 构成 `https://gezhiedu.feishu.cn/file/<file_token>`，但应以目录清单中的 URL 为准。向用户同时提供本地绝对路径、飞书文件链接、目标文件夹链接和本次版本号。

遇到授权、权限、配额、目标不存在等错误时停止，不改用其他账号或目录重试。只有服务端限流或临时网络错误可有限重试；重试前先列目录确认文件是否已创建，避免重复文件。
